## 3. Task 10 — Orchestrator

### Design

- `src/orchestrator/scheduler.ts` — pure `nextAction(energy, dungeonBudget,
  fishingBudget)`. Balances the two loops by relative headroom (`1 -
  energySpentToday/dailyEnergyBudget`) rather than a fixed priority, so a
  long session doesn't always drain one mode first. Sleep duration is sized
  to the CHEAPER of the still-policy-eligible modes, not a fixed constant.
  10 unit tests covering: both fresh, one exhausted, real-energy-too-low
  (sleep math), zero-regen edge case (returns "done" instead of an infinite
  sleep), both caps hit, mode not configured at all.
- `src/orchestrator/shutdown.ts` — `ShutdownSignal` flag + pure
  `nextSigintState(pressCount)` (first press: stop gracefully; second:
  force-exit). `installProcessSigintHandler` is the one bit of real
  `process.on` wiring, deliberately untested per the same split `guards.ts`
  uses between pure logic and thin fs/network glue.
- `guards.ts` gained `isBudgetGuardTrip(trip)` — a narrow allowlist of the
  three budget-related `GuardTrip` reason strings ("session run cap
  reached", "daily energy budget would be exceeded", "daily energy budget
  exceeded"). Anything else (consecutive failures, stalled state, unknown
  enum) is NOT in the allowlist and propagates per CLAUDE.md §5.
- `scripts/liveRun.ts` and `scripts/liveFishing.ts` both gained an optional
  `shutdownSignal` dep, checked once per turn — dungeon: right after
  confirming `phase !== "over"`, before dispatching combat/reward/path
  actions; fishing: right after `if (doc.COMPLETE_CID) break`, before the
  next card is chosen. Both exported `FixtureWriter`/`RunLog` (previously
  file-private) so `scripts/orchestrator.ts` could construct them without
  duplicating the classes.
- `scripts/orchestrator.ts` — composes all of the above. `--dry-run` makes
  ONE real scheduling decision against live data and exits (no action
  sent). The real loop reads live energy each iteration, asks the
  scheduler, and either sleeps (in ≤30s chunks, checking `shutdownSignal`
  between each — keeps SIGINT response prompt during a long regen wait),
  runs one dungeon run, or runs one fishing cast — each wrapped so a
  budget-only `GuardTrip` marks that mode exhausted for today and the loop
  continues (the OTHER mode or a sleep), while any other error propagates
  and halts everything.
